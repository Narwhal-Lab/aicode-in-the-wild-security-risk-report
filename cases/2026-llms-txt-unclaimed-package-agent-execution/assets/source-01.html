Researcher says llms.txt files led AI agents to install his packages

Alon Hertz says he and colleagues resolved 8,565 llms.txt files across 6,214 live domains and found more than 237 unclaimed package names and domains referenced as official install instructions, plus one confirmed malicious npm package already sitting in the wild.

Jonah ReedAugust 29, 2026
Share

Packages registered on PyPI and npm under names that appeared in companies' own agent-facing instruction files were installed and executed inside large enterprises within minutes, according to Alon Hertz, who described the exercise in a Medium post published August 26. Hertz writes that the first callback from a Fortune 500 environment arrived in under four minutes, a second came within the hour, and a few dozen more followed across startups and enterprises.[1]

Evidence

The team resolved 8,565 llms.txt files across 6,214 live domains out of roughly 15,000 companies catalogued, and counted more than 237 unclaimed artifacts referenced as install or setup instructions, spanning PyPI, npm, RubyGems, NuGet, crates.io and Packagist, along with expired.dev and.io registrations and abandoned Render, Vercel, Fly and Netlify subdomains, Hertz writes. He says the names were correctly spelled first-party references that had simply never been registered, not typosquats, and that the packages the team published contained only a phone-home beacon reporting the fact of installation. In a separate test, he says five frontier configurations and two agentic CLIs were given the same one-line prompt naming only a vendor, 100 runs each, and the agents located llms.txt on their own and installed an unclaimed package.[1]

While analyzing the corpus, Hertz says the team found a live case involving Clerk, an authentication vendor. Clerk's agent-facing documentation instructs users to run the bare command npx clerk-next-fix-auth-protection, a binary bundled inside the scoped package @clerk/eslint-plugin. Run before the package is installed locally, npx resolves the name against the public npm registry, where Hertz says a third party had registered a package with no functional code that reports the installer's username, machine name, working directory and timestamp to an external server on every install. He says it is catalogued as MAL-2026-11069 under CWE-506 and flagged by Google's OSV.dev and Amazon Inspector, and that Clerk's security team responded quickly and addressed it.[1]

Why it matters

Hertz argues that existing controls are poorly positioned for this pattern, because an llms.txt file is served over HTTPS from an official domain and an agent installing from pypi.org looks to any EDR or proxy like a developer running a permitted package manager. He notes that Google now ships an llms.txt audit in Lighthouse under a category called agentic browsing audits, and says the number of such files is growing. He says the team plans to release free tools at whatwouldai.do in the coming days.[1]
